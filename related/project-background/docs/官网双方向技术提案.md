# LumiQ 官网首页双方向技术提案

## 0. 结论

首轮不重做 Brand Story 与 Product 页面，只在现有信息结构上重做首页核心体验，并保留原有导航、文案主题与跳转关系。

两条路线都值得开发，但承担的职责不同：

- 方向一「媒体叠层与鼠标遮罩」适合做首屏钩子。它的优势是理解成本低、交互反馈直接、对素材连续性的要求相对可控。
- 方向二「视频锚定与滚动叙事」适合做品牌主叙事。它能把角色、产品和家庭场景组织成连续故事，但素材生产、视频编码和低端设备适配成本更高。
- 推荐的首页组合是：首屏用方向一抓住注意力；进入下一屏后，用方向二完成“角色出现—进入 Ola—产品苏醒”的连续叙事。

## 1. 研究结论

### 1.1 MotionSites

MotionSites 的页面本身是提示词与动效案例库。值得借鉴的不是它的黑色卡片墙，而是它把案例按交互职责拆成了 Reveal Hero、Cursor Follow、Portal、Cinematic Landing、Video Hero 等明确类型。每个案例先有主视觉，再有具体到字体、视频地址、布局位置、动效和断点的实施提示词。

对 LumiQ 最有价值的三个方法：

1. 一屏只设一个视觉主角，其他内容全部退后。
2. 动效必须有单一职责，例如“鼠标只负责揭示”“滚动只负责导演时间”，不要让同一个动作同时控制五种变化。
3. 提示词写成可执行规格：画面层级、镜头、字体、布局、动效范围、禁用项、移动端降级都要写清。

### 1.2 X 案例

- Romario 的长文强调：高级网站的差别来自限制条件、构图和系统，而不是“漂亮、未来感”之类的形容词。默认字体、三张功能卡、紫色渐变会让结果回到模板感。
- Grok + Cursor 案例展示了抽象三维主物体与大标题的配合。作者在评论中把素材与提示词统一导向 MotionSites，说明正确流程是先准备视觉资产，再开发动效。
- Gemini 3.6 Flash 的 F1 页面把人物、数据和地图固定成一张“信息海报”，再让动画负责节奏。作者评论区给出的提示词链接属于 MotionSites 付费内容，公开页只能确认入口与视觉结果。
- GPT Image + Claude Design 的机械手案例证明：生成图先决定页面的空间、留白和视觉焦点，再让代码还原。公开页显示“Prompt below”，但未登录状态下评论正文不可完整读取。
- Nano Banana + VEO 3 + Lovable 的 SkyElite 案例公开了完整提示词。其关键不是某个工具，而是规格精确：全屏循环视频、`object-cover`、固定导航宽度、标题负间距、按钮层级、字体、移动端菜单和颜色过渡都被写成可实现参数。

## 2. 视觉基线

### 2.1 保留

- 品牌核心：Play the Light、温暖科技、跨代陪伴。
- 主色：珊瑚橙、紫罗兰、奶油白、墨黑。
- 现有首页信息主题：AI Experiences for Families Across Generations、Where Technology Meets Wonder、产品与品牌故事入口。
- Ola 的核心几何：竖直展示舱、顶部摄像头、左侧三旋钮、厚实底座。

### 2.2 重做

- 原有产品渲染只作为几何参考，不直接用于成片。
- 场景、材质、光线、角色、镜头全部通过图生图重新生成。
- 从“金色塑料展示柜”升级为“深石墨黑、温润香槟金、微雾玻璃”的消费电子产品语言。
- 避免黑底霓虹、游戏设备和赛博朋克；高级感来自安静、真实、单一焦点和连续镜头。

## 3. 方向一：媒体叠层与鼠标遮罩

### 3.1 视觉逻辑

底层是 5 秒循环视频：Ola 从静默逐渐苏醒，紫色光环亮起，珊瑚橙与紫罗兰光粒聚合成陪伴者。上层是完全同机位的静态产品图。鼠标周围出现一个柔边圆形开口，只在开口范围内看到视频。

它不是“图片切换”，而是“静态现实下面藏着动态世界”。用户移动鼠标的行为，与“唤醒陪伴者”的品牌含义一致。

### 3.2 页面结构

1. 固定导航：保留 Home、Brand Story、Products。
2. 全屏媒体层：视频在底、静态图在上、色彩校正在最上。
3. 左侧主文案：沿用现有首页主标题，但改成更强的三行排版。
4. 鼠标提示：Move to wake Ola。
5. 主按钮跳转 Brand Story，次按钮跳转 Products。

### 3.3 实现

- 视频层：原生 `<video muted loop playsInline preload="auto">`。
- 静态层：完全同尺寸 `<img>`，使用 CSS `mask-image` 生成透明圆孔。
- 鼠标位置：`pointermove` 获取局部坐标，使用 GSAP `quickTo` 平滑写入 `--mx`、`--my`，避免每次事件触发布局计算。
- 圆孔半径：桌面端约 180px；触控设备没有悬浮概念，改成点击/拖动查看，或自动在产品周围缓慢巡游。
- 无障碍：开启“减少动态效果”时停止视频与鼠标追随，直接显示静态激活图。

### 3.4 素材规范

- 静态底图和视频首帧必须像素级同机位。
- 视频只允许角色、光粒、灯环和微弱反射变化，产品外壳、桌面、背景都不能漂移。
- 视频时长 4–6 秒；循环首尾亮度差不能过大。
- 桌面输出 H.264 MP4，建议另备 WebM；首屏文件尽量控制在 4MB 内。

### 3.5 风险

- 图生视频会让产品边缘轻微漂移。解决：提示词锁定镜头，并在视频外再覆盖静态产品轮廓；必要时只让舱内区域播放动态。
- 视频自动播放受浏览器限制。解决：始终静音、行内播放，并提供静态激活图作为后备。
- 鼠标快速移动时遮罩可能滞后。解决：只动画 CSS 变量，不改 React 状态，不触发组件重绘。

## 4. 方向二：视频锚定与滚动叙事

### 4.1 故事结构

首轮先做四个锚点：

1. K0：Ola 静默，房间安静。
2. K1：光之陪伴者在画面左侧出现，开始飞向 Ola。
3. K2：陪伴者正在穿过玻璃进入舱体。
4. K3：陪伴者完整进入，Ola 被点亮并挥手。

用 K1→K2、K2→K3 分别生成两段首尾帧视频，拼成约 8 秒主视频。后续可以继续增加 K3→家庭/平板生态的第三段。

### 4.2 页面结构

- 外层叙事容器高度约 520vh。
- 视觉层 `position: sticky; top: 0; height: 100vh`，滚动期间始终占满屏幕。
- 左侧文案分四章，与锚点对应。
- 右侧进度条展示 01–04，底部提示 Scroll to direct the film。

### 4.3 时间映射

设滚动区起点为 `start`，终点为 `end`：

```text
progress = clamp((scrollY - start) / (end - start), 0, 1)
videoTime = progress × videoDuration
```

GSAP ScrollTrigger 只负责计算进度和触发更新；视频保持暂停，通过设置 `currentTime` 跟随滚动。文案章节按进度切换，产品本身不再叠加额外浮动，避免“滚动、视频、页面元素各动各的”。

### 4.4 视频编码要求

- 主格式：H.264 MP4，1280×720 或 1920×1080。
- 必须执行 `faststart`，让视频元数据位于文件开头。
- 为提高拖动寻址速度，建议缩短关键帧间隔；首轮可设约 0.25–0.5 秒一个关键帧。
- 两段视频拼接前统一分辨率、帧率、色彩空间和音轨状态。
- 拼接处用同一张 K2 作为 A 段尾帧和 B 段首帧；如仍有亮度跳变，增加 4–8 帧交叉溶解。

### 4.5 性能与降级

- 桌面高性能设备：播放完整滚动绑定视频。
- 普通设备：视频仍绑定滚动，但降低到 720p。
- 移动端或省电模式：使用 K0–K3 图片交叉淡化，不强制逐帧寻址。
- 网络慢时先展示 K0，视频加载完成后无闪烁替换。
- `prefers-reduced-motion` 开启时改为四张静态章节图。

### 4.6 风险

- 长 GOP 视频在 Safari 上寻址会卡。解决：重新编码关键帧，使用短片段，预加载后再开放滚动。
- 多段 AI 视频会出现产品位置或角色形态漂移。解决：每段共享同一锚点图；摄像机、背景、产品都写入禁用变化项。
- 首屏就加载长视频会影响速度。解决：方向一视频优先，方向二进入视口前再预加载。

## 5. 首轮已完成的验证

- 生成方向一静默图、激活图与 5 秒首尾帧视频。
- 生成方向二 K0–K3 四张连续锚点图。
- 生成方向二 K1→K2、K2→K3 两段视频，并以 0.24 秒交叉过渡衔接成 7.875 秒完整叙事视频。
- 完成可运行的 React Demo：方向一实现图片叠视频的鼠标遮罩；方向二把完整视频暂停，并将播放时间与滚动进度逐帧绑定。
- 完成桌面端可用性核验：方向二视频可从 0 秒稳定推进到 7.59 秒，导航、方向切换与首页主要入口均可操作。
- 首页导航、Brand Story 与 Products 跳转沿用现站结构。

## 6. 下一轮建议

1. 先评审角色形态：更抽象的光丝精灵，还是偏人格化的光之人物。
2. 确认桌面端首页使用“方向一首屏 + 方向二第二屏”的组合，还是把两者做成两套独立版本。
3. 补做 K3→家庭/平板生态第三段，将产品叙事接回现有首页内容。
4. 根据最终镜头重新生成 1080p 视频，并做关键帧优化与移动端降级。
