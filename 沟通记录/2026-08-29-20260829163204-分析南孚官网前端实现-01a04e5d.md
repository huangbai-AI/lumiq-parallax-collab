## 核心实现

### 1. 超长容器负责制造滚动时间

桌面端几个核心段落分别设置为：

- 首屏：`300vh`
- 三大优势：`420vh`
- 品牌历程：`600vh`

容器里面放一个：

```css
.scene {
  height: 600vh;
}

.scene__viewport {
  position: sticky;
  top: 0;
  height: 100vh;
  overflow: hidden;
}
```

用户在外层继续向下滚动，里面的画面一直固定在屏幕中。网页只需要把该段滚动距离换算成 `0～1` 的进度。

`position: sticky` 的工作方式可参考 [MDN 说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position)。

### 2. 两组逐帧动画

页面一共观察到约 244 张图片，其中主要是：

- 首屏动画：120 张，尺寸约 `1920×1000`
- 电池历程：117 张，尺寸约 `500×150`
- 其余为产品图和装饰图

图片采用 WebP，抽样单帧约 18～46KB。两组素材粗略估算约 6MB。

网页根据滚动进度选择对应图片，再画到两个 `<canvas>` 上：

```js
const progress = Math.min(
  1,
  Math.max(0, (scrollY - start) / scrollDistance)
)

const index = Math.round(progress * (frames.length - 1))

requestAnimationFrame(() => {
  drawCover(context, frames[index], canvas)
})
```

这就是电池旋转、移动、形态变化非常稳定的原因：它本质上是预先渲染好的动画帧，不是浏览器实时计算三维模型。画布绘制方式可参考 [MDN Canvas 图片绘制](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Using_images)。

### 3. 三段视频负责复杂特效

页面加载了三段 WebM 视频：

- 首屏开场视频
- 电池内部进入动画
- 技术介绍背景循环视频

复杂的粒子、爆炸、光线和内部结构直接用视频完成；文字卡片、连接线和按钮仍然是普通网页元素，因此可以保持清晰和可交互。

### 4. 滚动进度直接控制 CSS 动画

它用了一个很巧的方案：

```css
.scrub-animation {
  animation-duration: 1s;
  animation-play-state: paused;
  animation-delay: calc(var(--go) * -1s);
}
```

脚本只需要持续更新：

```js
element.style.setProperty("--go", progress)
```

就可以让 CSS 动画停在指定进度。页面里的遮罩切换、文字显现主要使用：

- `clip-path`
- `opacity`
- `transform`
- 自定义贝塞尔曲线
- 分字错位进场

运行时样式也呈现出明显的 GSAP 动画痕迹。若重新实现，可以直接采用 [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)，它原生支持滚动绑定、固定、横向运动和进度跟随。

### 5. 竖向滚动转横向时间轴

品牌历程依然是竖向滚动，但内部轨道做横向位移：

```js
const maxX = track.scrollWidth - window.innerWidth
track.style.transform = `translate3d(${-progress * maxX}px, 0, 0)`
```

中间电池同时根据同一进度切换117张动画帧，所以时间节点、文字、电池运动可以保持同步。

### 6. 产品与信息卡片使用轮播组件

页面出现了标准的：

- `swiper-wrapper`
- `swiper-slide`
- `swiper-slide-active`

因此产品卡片和移动端横滑内容基本可以判断为 [Swiper](https://swiperjs.com/swiper-api)。

## 页面技术架构判断

从公开页面痕迹看，它更像：

- 服务端直接输出完整 HTML
- 原生脚本或定制模块控制页面
- 现代模块包 + 兼容包两套脚本
- GSAP 类动画方案
- Swiper 轮播
- Canvas 2D 逐帧合成
- WebM 视频
- CSS `sticky`、`clip-path`、模糊背景

没有明显的 React、Next、Nuxt 或实时 Three.js/WebGL 痕迹。

## 响应式做法

它不是简单缩小桌面端，而是准备了两套布局：

- 横屏显示 `.pc`
- 竖屏显示 `.app`
- 桌面三栏产品卡片，手机改为纵向排列
- 桌面技术说明悬浮在画面上，手机改为横滑卡片
- 手机取消部分超长固定动画，避免滚动体验过重
- 桌面用 `html { font-size: 5.20833vw }`，即1920宽度下 `1rem≈100px`
- 手机字体大量改用 `vw`

## 值得借鉴和需要改进的地方

值得借鉴：

- 用离线渲染帧替代实时三维，产品效果稳定
- 用视频处理复杂粒子，用网页元素承载文字
- 一套滚动进度同时控制画布、文字和横向位移
- 固定视口配超长容器，结构清晰
- 移动端单独设计交互，不强行复用桌面效果

需要改进：

- 237张动画帧加三段视频，首屏和弱网加载压力较大
- 建议只预载前10～20帧，其余分批加载
- 需要增加低性能设备降级方案
- 应补充 `prefers-reduced-motion`，照顾不希望看到强动效的用户
- 视频最好增加 MP4 或静态封面兜底
- 逐帧动画应在离开视口后暂停刷新

如果要在 LumiQ 里复刻这种效果，我建议采用“React/Vue均可 + GSAP ScrollTrigger + Canvas逐帧 + Swiper”，不需要引入 Three.js。这样能还原约八九成视觉效果，同时开发成本和稳定性更可控。

## 方案一：品牌叙事型，7层，推荐

1. 品牌首屏：一句品牌主张、三款产品家族视觉、主按钮。
2. 品牌起点：为什么创立 LumiQ，家庭科技目前有什么问题。
3. 产品生态：三款产品集中在一层，说明各自角色及相互关系。
4. 核心产品：只保留 Ola 一个完整产品楼层。
5. 家庭的一天：用早晨、放学后、夜晚串起三款产品。
6. 信任证明：隐私安全、儿童内容原则、团队、媒体评价或测试数据。
7. 加入候补名单与页脚。

理由：产品曝光没有减少，但首页从“卖三件产品”变成“讲一个家庭科技品牌”。
